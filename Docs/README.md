## Maintenance and generated output

- Edit one topic in its source file. The guide is navigation; it does not duplicate topic chapters.
- Use ordinary Markdown and repository-relative links. Chinese names and dialogue remain in examples
  to demonstrate Unicode authoring; explanatory prose, titles, descriptions and comments are English.
- `diagnostics/` is a manually maintained compiler reference, not reflection-generated API output.
  Keep code identifiers stable and document the trigger, rationale and fix for every emitted code.
  Check the lexer, parser, validator and toolchain diagnostic sites when changing that reference.
- The site repository's `docs-sync/config.json` maps these sources to stable page IDs. A file move
  requires a mapping update, not a public URL change. Its `exclude` list keeps this repository-only
  navigation file out of automatic page discovery, and translation status skips it for the same reason.
- Site English pages and `docs-sync/source-lock.json` are generated by `dreamdocs site sync` in the
  site repository. Update plugin sources and rerun that sync; do not maintain those outputs by hand.
- If generated API references are added later, record their generator and input headers next to the
  output, and change the inputs rather than editing generated files.
- `Config/FilterPlugin.ini` includes `/Docs/...`, so these topic directories ship with the plugin.

The former combined `Guide.md`, `Diagnostics.md` and `Architecture.md` have been organized into these
topics; `Architecture.md` now lives under `contributing/`. Website page IDs remain unchanged. This
index is repository navigation only: the site excludes it and it is never translated.

The `zh-CN/` tree mirrors English source paths. Beside it, `zh-CN/.align/` records which English paragraph each Chinese paragraph was translated from, so when the English changes only the changed paragraphs are translated again. Correct a translation by editing the Chinese page directly; the next run keeps the edit. Website-only notes remain in the website repository.

Translations are made and checked with [dreamdocs](https://github.com/TypeDreamMoon/dreamdocs): `dreamdocs status` lists the stale and missing paragraphs, `dreamdocs translate` translates them, and `dreamdocs check --plugin .` is what CI runs. Its settings for this plugin are in `dreamdocs.json`.
